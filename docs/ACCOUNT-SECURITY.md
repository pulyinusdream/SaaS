# Account settings and session security

Approved milestone: profile display name, authenticated password change and active-session controls. Continue inline under the user's explicit instruction. Existing Flask/Jinja/SQLite, mint framed sheet seed716491800, IBM Plex Sans/SVGs remain. No dependency, public deployment, SMTP, email-address change, MFA, billing or account deletion.

Account scope: owner and dispatcher can manage only their own account across all workspaces, including accounts with no workspace. GET /account/settings and POST /account/profile, /account/password, /account/sessions/revoke-others. These self-service endpoints stay accessible when email verification is required; workspace access remains gated. All writes use existing CSRF/origin protection. Submitted user/company IDs never select the target.

Profile: required trimmed display name, 1–100 characters, no control/format characters. Escape rendered text. Add users.profile_version default1 for stale-form rejection409 with reload; don't overwrite a newer profile. Existing historical event actor strings stay unchanged, current assignment names follow the user's current profile. Email remains read-only and links to existing verification flow.

Password: require current password; new password12–128 characters, confirmation and different from current. Retain no password values in HTML/logs/URLs. Existing scrypt hashing and password-manager/paste support. Throttle password reauthentication with the existing persisted rate limiter (10 attempts per15minutes peraction/IP). Validate current hash outside the write lock, then BEGIN IMMEDIATE and refresh active session/user; compare expected credential hash before mutation. Successful password change updates the hash and atomically revokes ALL sessions and unused recovery/verification links, clears the current browser session, and redirects to sign-in. No automatic email claims. Reauthentication changes no email-verification state.

Sessions: list only this account's unexpired server sessions, current session first,25/page, count from same read transaction. Show true sign-in/expiry UTC timestamps. New session_details table keyed to session digest with ON DELETE CASCADE stores creation and a bounded allowlisted browser/platform label, never raw user-agent/IP/device fingerprint. Existing sessions have no invented creation/browser metadata. Labels are client-reported hints, not verified devices. Shared browser tabs may share one session. No raw session token/digest in page or action URL. Session list doesn't claim live device activity or last-seen tracking.

Revoke others: current password required; BEGIN IMMEDIATE refresh/credential comparison as above, delete only this user's other sessions including expired rows. Leave this exact current session and other users untouched. No-op success if none remain; disabled action when none on display. A subsequent login may create a new session. A session revoked/expired after identity loading must not complete a profile/password/revocation write. Concurrent password changes or reset interactions cannot restore a stale credential/session. Logout/expiry/password reset cascades metadata cleanup. Backup recovery enables foreign keys so deleting sessions removes new metadata; older backups remain valid.

UI: Account settings link replaces email-verification-only navigation (verification accessible in account page/banner). Three anchored sections: Profile, Password, Active sessions; visible personal-account scope and consequences. Consistent section grid, no metric cards or new decorative system. Existing pending/error-summary/focus behavior, keyboard/semantic labels, readonly email, password autocompletion, no paste blocking. Responsive rows stack on phone, visible loading/success/error/stale/disabled/no-other-session states. Public narrow fallback gets a workspace return link where applicable.

Verification: test-first real Flask/SQLite requests and separate synthetic browser data. Cover owner/dispatcher/no-workspace/strict-verification, validation/escaping/stale profile, wrong/missing/same/long passwords, all-session/token invalidation, replayed cookies, isolation, expired/revoked midrequest, credential race, metadata/legacy/pagination, backup recovery and rate limits. Native browser QA does not change any real credential; exercise profile/revocation only on fixtures, inspect password UI and test credential mutation via isolated integration tests. Fresh read-only security review before delivery. Verified private backup and fresh original-column hashes before activation; preserve all existing real data/key, update README/VERIFICATION/source ZIP.
